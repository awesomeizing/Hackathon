## SLIDE 4 — Privacy Boundary (Trust Boundary)

### Two-Tier Data Separation

```
┌─────────────────────────────────────────────────────────┐
│  TIER 1 — LOCAL ONLY (never leaves the edge collector)  │
│                                                         │
│  • Raw lines containing ANY regex-matched secret        │
│  • secrets_kept_local: 6  (from run-2026-11-20T1044Z)  │
│  • secrets_seen session: 0  (current clean stream)      │
│  • Raw SQLite WAL file (plain text — not encrypted*)    │
│  • raw_ttl_min: 60  (auto-pruned after 1 h)            │
└─────────────────────────────────────────────────────────┘
            │  ALLOW-LIST FILTER (pipeline.js)
            │  Only these fields may egress:
            │  host, kind, ts, category, level, message
            ▼
┌─────────────────────────────────────────────────────────┐
│  TIER 2 — SANITISED EGRESS (SaaS / cloud)               │
│                                                         │
│  • JSON payload with only allow-listed fields           │
│  • SHA-256 Signal Passport computed over canonical form │
│  • HTTPS POST to SaaS /v1/ingest                        │
│  • SaaS returns receipt_digest (echo of passport_sha256)│
│  • Receipt stored locally; match checked in UI          │
└─────────────────────────────────────────────────────────┘
```

> **\* KNOWN GAP:** SQLite at rest is NOT encrypted. Noted in CLAIM_LEDGER.md.
>
> **ILLUSTRATIVE EXAMPLE** — The tier diagram above is correct for all stream kinds.
> Secret counts shown are from real pipeline runs; no values are fabricated.

## SLIDE 5 — Egress Proof (Receipt Match)

### Live Digest Match Evidence

Captured from API during prior verified session (`run-2026-11-20T1044Z`):

| Field | Actual Value |
|-------|-------------|
| Payload seq | 5 384 |
| `passport_sha256` | `741e7a8e96bf5bdf…` |
| `receipt_digest` | `741e7a8e96bf5bdf…` (identical) |
| `match` | `1` ✅ |

**What this proves:**
- The same SHA-256 that the collector computed over the canonical sanitised JSON was returned verbatim by the SaaS after storing the payload.
- The receipt chain (ingest → store → deliver → verify) works end-to-end on the simulated stream.

**What this does NOT prove:**
- That the SaaS independently recomputes the hash (it currently echoes the ingest value).
- That the pipeline has been tested with organizer-stream payloads.
- Cryptographic non-repudiation (no asymmetric signing; noted as gap in CLAIM_LEDGER.md).

> **UI behaviour (EgressProofPanel.jsx):** receipt card is conditional — it shows PENDING until `passport_sha256 === receipt_digest`; no hardcoded fallback digest is ever shown.

## SLIDE 11 — Architecture Overview

```
┌────────────────────────────────────────────────────────────────────┐
│                        SOURCE HOSTS                                │
│  sim-stream.js :7200  →  events (log, auth, metric, trace, net)   │
└──────────────────────┬─────────────────────────────────────────────┘
                       │  HTTP POST /v1/event
                       ▼
┌────────────────────────────────────────────────────────────────────┐
│          COLLECTOR  :7100  (collector/index.js)                     │
│                                                                    │
│  1. Receive raw event                                              │
│  2. Secret scan  →  STAY LOCAL if hit                              │
│  3. Allow-list filter  →  strip disallowed fields                  │
│  4. Batch into payload (window_ms: 2 000)                          │
│  5. Compute SHA-256 Signal Passport over canonical JSON            │
│  6. HTTPS POST to SaaS /v1/ingest                                  │
│  7. Store receipt_digest from SaaS response                        │
│  8. Expose /api/state, /api/delivery, /api/payload/:id             │
└──────────────────────┬─────────────────────────────────────────────┘
                       │  HTTPS /v1/ingest (TLS)
                       ▼
┌────────────────────────────────────────────────────────────────────┐
│          SAAS  :8080/:8443  (saas/server.js)                       │
│                                                                    │
│  • Receives sanitised payload + passport                           │
│  • Stores to SQLite (WAL mode)  — Supabase: not configured         │
│  • Returns receipt_digest (echo of passport_sha256)                │
│  • Anomaly detection (Z-score per metric, baseline rolling)        │
│  • Alert/incident generation with reasoning[]                      │
│  • Exposes /api/overview, /api/stream (SSE), /api/series           │
└──────────────────────┬─────────────────────────────────────────────┘
                       │  SSE / polling
                       ▼
┌────────────────────────────────────────────────────────────────────┐
│          REACT COMMAND CENTER  (web/src)                           │
│                                                                    │
│  • Stream badge: SIMULATED (amber) / ORGANIZER STREAM (emerald)    │
│  • Counts ribbon: acked / pending / rejected / buffered / secrets  │
│  • GlyphCurtainHero: ILLUSTRATIVE EXAMPLE / LIVE DATA banner       │
│  • SecretInspector, IncidentRemediation, SlaMetricsPanel           │
│  • EgressProofPanel: conditional on actual digest match            │
```
